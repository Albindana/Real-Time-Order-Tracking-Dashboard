Real-Time Order Tracking Dashboard

What is this project, in plain language?

SignalR · Redis · ASP.NET Core · React
EASY

The One-Sentence Pitch

Memorize this: "It's a real-time order dashboard where an ASP.NET Core API pushes live updates to a React client over a SignalR WebSocket, and Redis pub/sub decouples the broadcast from the request that triggered it."

What does it actually do?

Imagine the screen a shop manager watches all day. Every time a customer places an order, it appears on the dashboard instantly — no refresh, no waiting. The revenue counter ticks up, the "pending orders" number changes, and low-stock warnings pop up automatically.

The whole point is that the screen updates by itself, the moment something happens.
EASY

The Problem It Solves

❌ The old way: Polling

The browser keeps asking the server "anything new? anything new?" every second.

  • Wasteful — usually the answer is "no"
  • Updates still lag by up to a second
  • 100 users = 100 requests/second of noise

✅ This project: Pushing

The server pushes updates to the browser only when something changes.

  • Instant — zero polling
  • One permanent connection per user
  • Done with SignalR (WebSockets)

The key ingredients in plain words

  • SignalR — lets the server push messages to the browser live. Like a phone line that stays open instead of texting back and forth.
  • WebSocket — the actual "always-open connection" SignalR uses.
  • Redis — a super-fast store used as a "message bus" (drop a note saying "an order happened!") and as a cache for the dashboard numbers.
  • Database (SQLite) — where orders, products, and users are permanently saved.
  • JWT — a secure token you get when you log in that proves who you are.
  • Docker — packages everything so it runs with one command.

🎤 Interview Questions

Q: What does this project do?
It's a dashboard showing live order activity for a store. When an order is placed or changes status, every connected dashboard updates instantly without refreshing.
Q: What makes it "real-time"?
SignalR, built on WebSockets. It keeps a permanent connection open so the server can push updates the moment they happen.
Q: Why not just poll the server?
Polling wastes resources and still lags. Pushing with SignalR is instant and only sends data when something actually changes.
EASY

🎤 Interview Questions (cont.)

Q: What did you use for frontend and backend?
React with TypeScript on the frontend, ASP.NET Core (C#) on the backend, with Redis and a SQL database behind it.
Q: What is Redis used for, simply?
Two things: a fast cache for the dashboard numbers, and a "message bus" — when an order happens the API drops a message into Redis, and a background process picks it up and broadcasts it.
Q: How do you run it?
One command: docker compose up. That starts the database/Redis, the API, and the frontend together.
